# Media Happi Brand Guidelines

These guidelines define the visual, technical, and communication standards for Media Happi products, websites, and repositories.

Consistency across platforms strengthens trust, recognition, and perceived engineering quality.

This is a **real system used in production**, not just a visual reference.

---

# 1. Logo

[![Media Happi AI Logo](https://mediahappi.com/wp-content/uploads/2025/02/MEDIA-HAPPI-LOGO-0011-copy.png.webp)](https://mediahappi.com)

### Usage Rules

- The logo must always appear clearly and proportionally.
- Do not stretch, recolor, distort, or modify the logo.
- Maintain adequate whitespace around the logo.
- Use the correct variation depending on background contrast.
- Always link the logo to:
  
https://mediahappi.com

### Advanced Rules

- No shadows or effects
- No overlays or text on top
- Do not crop the logo
- Always ensure strong contrast with background

---

# 2. Color System (CORRECTED FOR REAL USAGE)

### Core Colors

| Purpose | Color | HEX |
|--------|------|-----|
| Primary Background | Black | `#000000` |
| Secondary Background | Navy | `#0A102F` |
| Card Background | Dark Gray | `#1B1C1D` |
| Primary Accent | Blue | `#3251FC` |
| Hover / Active | Dark Blue | `#1F3BBF` |
| Accent | Purple | `#A259FF` |
| High Emphasis CTA | Green | `#C1FF00` |
| Primary Text | White | `#FFFFFF` |
| Secondary Text | Light Gray | `#CFCFCF` |

### Critical Rule (DO NOT BREAK)

- **Dark background → Light text ONLY**
- Never use black text on dark backgrounds
- White (`#FFFFFF`) is the default text color
- Light gray is used for secondary text only

### Usage

Primary blue should be used for:

- headings
- links
- UI highlights
- call-to-action elements

Dark blue is used for hover states and active UI states.

### System Rules

- Always design for dark UI
- Maintain high contrast at all times
- Do not introduce random colors
- Accessibility and readability override design preference

---

# 3. Typography

Typography should feel modern, technical, and highly readable.

### Headings

| Element | Font | Weight | Size | Color |
|--------|------|--------|------|------|
| H1 | Unbounded | Bold | 36px | `#3251FC` |
| H2 | Unbounded | SemiBold | 28px | `#3251FC` |
| H3 | Unbounded | SemiBold | 24px | `#3251FC` |

### Body Text

| Element | Font | Size | Color |
|--------|------|------|------|
| Paragraph | Poppins | 16px | `#FFFFFF` |
| Secondary Text | Poppins | 16px | `#CFCFCF` |
| Links | Poppins | 16px | `#3251FC` |

Hover color for links:

`#1F3BBF`

### Rules

- No decorative fonts
- Maintain strict hierarchy
- Optimize for readability first
- Always consider contrast against dark backgrounds

---

# 4. Buttons

Buttons should feel clean, minimal, and modern.

| Property | Value |
|---------|------|
| Font | Poppins |
| Font Size | 16px |
| Text Color | White |
| Background | `#3251FC` |
| Border | none |
| Border Radius | 6px |
| Hover Background | `#1F3BBF` |
| Hover Text | White |

### Button Types

- Primary → Blue
- Secondary → Outline
- High-emphasis → Green (`#C1FF00`)

### Rules

- Always action-driven
- Must be clearly visible on dark backgrounds
- No low-contrast buttons
- No inconsistent styles

---

# 5. Navigation

Navigation should feel lightweight and modern.

| Property | Value |
|---------|------|
| Font | Poppins |
| Size | 16px |
| Color | `#3251FC` |
| Hover | `#1F3BBF` |
| Active Page | `#1F3BBF` |

### Rules

- Keep navigation minimal
- Avoid clutter
- Ensure strong contrast
- Maintain consistency across all pages

---

# 6. Visual Style

### Images

Images should feel:

- professional
- modern
- high contrast
- technology oriented
- minimal when possible

### Icons

Use simple, minimal icon sets.

Recommended:

- outline icons
- geometric icons
- monochrome icons

Avoid:

- cartoon style graphics
- overly complex illustrations

### Rules

- Visuals should support clarity, not decoration
- Avoid unnecessary imagery
- Maintain consistency across platforms

---

# 7. Voice & Tone

Media Happi communication style:

Professional but optimistic.

Clear but forward-thinking.

Engineering-focused but accessible.

### Tone characteristics

- confident
- intelligent
- calm
- future-focused
- practical

### Expanded Writing Rules

- Use short, direct sentences
- Avoid filler words
- Avoid buzzwords
- Be specific, not abstract
- Focus on action and clarity

### Examples

Bad:
- Leverage AI ecosystems  
- Unlock your potential  

Good:
- Write your script  
- Generate your content  
- Publish instantly  

---

# 8. CTA System

Approved CTAs:

- Start Free →
- Get Access →
- Generate Now →
- Build Now →

### Rules

- Always action-based
- Never vague
- Must clearly define next step
- Avoid “Learn More” unless paired with action

---

# 9. Layout & Structure

### Core Structure

- Hero
- Alternating dark sections
- Feature blocks
- Final CTA

### Rules

- Maintain vertical rhythm
- Avoid cluttered layouts
- Keep spacing consistent
- Prioritize readability

---

# 10. Component System

### Cards

- Dark background
- Subtle borders
- Consistent padding

### Lists

- Clean structure
- Simple icons (✓)

### Rules

- Reuse components
- Do not invent new patterns unnecessarily
- Maintain system consistency

---

# 11. Development Rules

- Keep UI consistent across repos
- Avoid one-off styling
- Follow system strictly
- Build reusable components

---

# 12. AI Generation Rules

- Output must follow this system
- Must use approved voice and tone
- Must follow layout + structure
- No random styles or formatting

---

# 13. Accessibility & Performance

### Accessibility

- High contrast text
- Clear hierarchy
- Readable font sizes

### Performance

- Optimize assets
- Keep UI lightweight
- Avoid unnecessary dependencies
